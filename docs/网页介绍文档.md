# weimou_web 项目说明

> 面向内部同事的项目介绍和维护说明。  
> 最后更新：2026-08-05

## 1. 先看这里

这个项目就是 weimou_web，主要做三件事：

1. 展示公司和产品资料。
2. 维护新闻、荣誉等官网内容。
3. 收集客户线索，方便销售和业务同事跟进。

项目目前已经包含中英文页面、移动端适配、产品视频、新闻/荣誉数据同步和联系表单。页面不是传统多页面应用，而是 React 外壳加 Hash 路由：访问地址中的 `#/home`、`#/about` 等部分决定当前显示哪个页面。

这份文档主要给后续需要改页面、改文案、接数据或部署项目的同事看。页面视觉细节以实际运行效果为准，本文重点记录功能和实现方式。

## 3. 各页面现在做了什么

### 首页

- 顶部 Hero 展示公司定位。
- 中间有产品焦点轮播，当前展示药物精准递送系统、OIS 和手术耗材。
- 产品管线用横向卡片展示四类产品。
- 下方是公司简介、关键数字和新闻摘要。
- 页面底部有“获取方案”入口，会跳到联系我们。

首页上的产品卡片、轮播圆点和左右箭头都由 `bindInteractions()` 绑定交互。

### 关于我们

- 企业介绍和公司关键数据。
- 企业介绍视频。
- 2011 年至今的发展历程时间轴。
- 企业文化：价值观、愿景使命、业务目标。
- 企业荣誉，支持发明专利、相关荣誉、学术成果分类切换。

荣誉内容如果接了飞书，会优先显示本地同步缓存；飞书暂时不可用时，页面还能显示上一次同步成功的内容。

### 产品页

药物精准递送系统页主要讲科研使用场景：7 自由度运动、自适应 RCM、微量注射、穿刺、剥膜，以及鼠、兔、猴、犬、羊、猪等实验对象。

OIS 页使用 Tab 切换功能模块，内容包括图像导入、图像处理、数据安全、多维标注、材料归档、流程管理和智能分析。

WMOX-22001 页主要展示：

- 末端 3–5 μm 精度。
- 远心运动精度 100 μm 以内。
- 运动闭环控制周期小于 30 μs。
- RCM 控制和多自由度运动。
- 穿刺、注射、剥膜、夹取等动作。
- 模块化设计及 5G 远程操控能力。
- 产品视频、临床案例和临床进展。

WMOX-24001 当前只是预告页，后续有完整资料时再扩充。

手术耗材页通过分类按钮筛选产品。分类值是 `needle`、`instrument`、`kit`、`experiment` 和 `other`，新增耗材时要注意分类值和筛选按钮保持一致。

### 新闻中心

- 顶部展示推荐新闻轮播。
- 新闻列表支持按年份筛选，默认“全部年份”展示所有文章。
- 列表支持分页。
- 配置飞书后，勾选“官网展示”且发布日期包含年份的新闻都会显示；分类、标签和封面图不影响列表展示。

目前新闻列表有内置数据作为兜底，飞书同步成功后页面会读取本地新闻缓存。

### 服务支持和联系我们

服务支持页展示三类培训课程，同时有销售热线、售后热线和线索表单。

联系我们页是独立的商务咨询页面，也使用同一套线索提交逻辑。表单字段为：姓名、电话、公司名称、邮箱、留言内容。

前端会先做必填、电话和邮箱校验；服务端会再次校验，不能只依赖前端校验结果。

## 4. 统一交互

- 顶部可切换中文和英文，选择结果会存到浏览器本地存储。
- 移动端顶部导航通过菜单按钮展开和关闭。
- 页面滚动时会显示滚动进度，滚动较深后出现返回顶部按钮。
- 首页、新闻、荣誉等模块有轮播或左右切换。
- OIS 和耗材使用当前页面内切换，不会改变 URL。
- 产品介绍视频可以在弹窗中打开。
- 支持 `Esc` 关闭视频弹窗。
- 支持 `prefers-reduced-motion`，用户系统设置为减少动效时会降低动画。
- 页面给主要按钮、轮播、Tab、弹窗和表单补了基础无障碍属性。

## 5. 视频播放器

视频不是直接使用浏览器默认控件，而是通过 `src/pot-player.js` 增强。当前支持：

- 播放、暂停、进度拖动。
- 前进/后退 10 秒。
- 静音和音量调节。
- 0.5×、0.75×、1×、1.25×、1.5×、2× 倍速。
- WebVTT 字幕开关。
- 画中画和全屏。
- 配置多码率源后切换清晰度。
- 将当前显示的审核字幕发送到服务端配置的翻译服务，进行 AI 翻译。

视频由 `server.js` 提供静态文件和 HTTP Range 分段响应，拖动进度条时不需要每次重新读取整个 MP4。

AI 翻译只处理当前显示的字幕文本，不上传视频音频；翻译服务密钥只放在服务端环境变量中。接口默认按来源 IP 每分钟最多处理 30 次请求。

## 6. 技术结构

### 前端

- React 19：负责应用挂载和页面生命周期。
- Vite 7：负责开发服务器和生产构建。
- `src/main.jsx`：React 入口，监听 Hash 路由和语言切换。
- `app.js`：页面模板、路由映射和大部分页面交互。
- `i18n.js`：中英文文案映射和语言状态处理。
- `styles.css`：全局样式、响应式布局、动效和页面视觉。
- `src/pot-player.js`：视频播放器、字幕和 AI 翻译交互。

当前页面的 HTML 主要由 `app.js` 中的函数生成，例如 `homePage()`、`aboutPage()`、`researchPage()`。React 通过 `dangerouslySetInnerHTML` 把这些模板挂到页面中，然后由 `bindInteractions()` 统一绑定 DOM 事件。因此改一个页面时，通常需要同时看对应的模板函数和 `bindInteractions()` 中的交互代码。

### 后端

`server.js` 是原生 Node.js HTTP 服务，负责：

- 静态资源和视频文件。
- API 路由。
- 联系表单写入飞书。
- 新闻和荣誉从飞书同步到本地缓存。
- 新闻/荣誉图片缓存和读取。
- MP4 Range 分段响应。
- 服务端调用 AI 字幕翻译服务。

项目没有引入 Express，新增接口时需要按现有 `server.js` 的请求解析、响应和错误处理方式实现。

### 数据流大致是这样

```text
浏览器
  ├─ 静态资源 / 视频 ──> server.js
  ├─ POST /api/leads ──> 飞书线索表
  ├─ GET /api/news ────> data/news/news.json
  ├─ GET /api/honors ──> data/honors/honors.json
  └─ POST /api/translate-captions ──> 服务端配置的翻译服务

飞书新闻表 ──定时同步──> data/news/
飞书荣誉表 ──定时同步──> data/honors/
```

## 7. API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/health` | 检查 API 是否正常 |
| `POST` | `/api/leads` | 校验并提交联系线索 |
| `POST` | `/api/translate-captions` | 调用字幕翻译服务 |
| `GET` | `/api/news` | 读取新闻本地缓存 |
| `GET` | `/api/news/image` | 读取新闻封面图 |
| `GET` | `/api/honors` | 读取荣誉本地缓存 |
| `GET` | `/api/honors/image` | 读取荣誉图片 |

### 线索接口的保护

`POST /api/leads` 当前有这些限制：

- 请求体大小和字段长度限制。
- 姓名、电话、公司、邮箱必填。
- 电话和邮箱格式校验。
- 隐藏字段蜜罐拦截。
- 默认 10 秒最多 2 次、60 秒最多 5 次。
- 全局并发和单客户端并发限制。
- 通过 `X-Idempotency-Key` 和内容指纹防止重复提交。
- 限制触发时返回 `429` 和 `Retry-After`。

这些限制是单个 Node 进程内存级别的。正式环境仍建议在前面加 CDN/WAF 或反向代理；多实例部署时，限流状态要考虑放到 Redis 等共享存储。

## 8. 飞书数据同步

新闻和荣誉都不是浏览器直接访问飞书，而是由服务端定时同步：

1. `server.js` 使用飞书应用凭证获取访问令牌。
2. 读取对应多维表格记录。
3. 过滤“官网展示”关闭的记录。
4. 将新闻/荣誉图片下载到本地缓存目录。
5. 写入 JSON 缓存文件。
6. 浏览器访问 `/api/news` 或 `/api/honors` 时读取本地缓存。

这样做的好处是飞书临时不可用时，官网还能继续展示上一次同步成功的内容。同步失败时不要直接清空旧缓存。

新闻默认缓存目录是 `data/news/`，荣誉默认缓存目录是 `data/honors/`。同步周期默认 5 分钟，可通过环境变量调整。

## 9. 环境变量

服务端会读取根目录下的 `.env` 和 `weimou_web.env`。配置优先级以项目 README 中的说明为准：进程环境变量优先，其次是 `.env`，最后是 `weimou_web.env`。

常用配置如下：

```env
FEISHU_APP_ID=cli_xxxxxxxxxxxxx
FEISHU_APP_SECRET=xxxxxxxxxxxxxxxx

FEISHU_BITABLE_APP_TOKEN=xxxxxxxxxxxxxxxx
FEISHU_BITABLE_TABLE_ID=tblxxxxxxxxxxxxx
FEISHU_FIELD_NAME=姓名
FEISHU_FIELD_PHONE=电话
FEISHU_FIELD_COMPANY=公司名称
FEISHU_FIELD_EMAIL=邮箱
FEISHU_FIELD_MESSAGE=留言内容

FEISHU_NEWS_APP_TOKEN=xxxxxxxxxxxxxxxx
FEISHU_NEWS_TABLE_ID=tblxxxxxxxxxxxxx

FEISHU_HONORS_APP_TOKEN=xxxxxxxxxxxxxxxx
FEISHU_HONORS_TABLE_ID=tblxxxxxxxxxxxxx

AI_TRANSLATION_URL=https://your-approved-ai-translation-service.example/v1/translate
AI_TRANSLATION_TOKEN=replace-with-server-side-secret

API_PORT=8787
```

真实 `.env` 不要提交到 Git。修改飞书字段名时，要同步更新环境变量和对应表格字段。

## 10. 目录和常用文件

```text
weimou_web/
├── app.js                  # 页面模板、页面路由和交互绑定
├── i18n.js                 # 国际化文案
├── styles.css              # 全局样式
├── src/main.jsx            # React 入口
├── src/pot-player.js       # 视频播放器
├── server.js               # Node API、静态资源和飞书同步
├── assets/                 # 图片、视频、字体等素材
├── data/news/              # 新闻缓存
├── data/honors/            # 荣誉缓存
```

改文案时，优先看 `app.js` 和 `i18n.js`；改布局和视觉看 `styles.css`；改接口、缓存或飞书逻辑看 `server.js`；改视频能力看 `src/pot-player.js`。

## 11. 本地运行和发布前检查

安装依赖并启动开发环境：

```powershell
npm.cmd install
npm.cmd run dev
```

默认地址：

- 前端：`http://127.0.0.1:4175`
- API：`http://127.0.0.1:8787`

构建和检查：

```powershell
npm.cmd run build
npm.cmd run test:interactions
npm.cmd run test:range
npm.cmd run test:visual
npm.cmd run preview
```

发布前建议至少检查：

- 首页、产品页、新闻页和联系页能正常打开。
- 中文/英文切换后刷新页面仍保持语言。
- 移动端导航能展开和关闭。
- 新闻和荣誉接口有数据时能正常展示，无数据时有兜底内容。
- 联系表单的必填、电话、邮箱校验和重复提交限制正常。
- 视频播放、拖动、字幕、全屏和 Range 请求正常。
- 构建产物能通过 `preview` 启动。

## 12. 后续改动时容易踩坑的地方

- 页面通过 Hash 路由切换，新增页面要同时加入 `pages` 映射、导航入口和 `PRODUCT_ROUTES`（如果属于产品页）。
- `app.js` 的页面模板和 `bindInteractions()` 是分开的，新增 `data-*` 交互时不要忘记补事件绑定和清理逻辑。
- 新闻、荣誉图片依赖缓存文件，不能只改 JSON 而漏掉图片文件。
- 联系表单不能只改前端字段；服务端字段白名单、长度限制和飞书字段映射也要一起改。
- 视频如果增加字幕，需要确认 WebVTT 轨道配置正确；如果增加清晰度，需要给 `<video>` 配置 `data-quality-sources`。
- `.env`、`weimou_web.env` 以及其中的飞书和翻译服务密钥不要提交。
- 多实例部署时，当前内存限流实现不能替代共享限流或 WAF。
